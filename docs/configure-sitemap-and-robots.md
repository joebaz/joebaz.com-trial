# Configure the sitemap and robots.txt

The build generates crawl-discovery files during `npm run build`. The production URL comes from `production_url` in [website-facts.yaml](../website-facts.yaml), the same source used by [page metadata](configure-site-and-pages.md); Astro's build sets its `site` option from it. Use the approved production URL, never a development or preview host.

## Build behavior

With the production URL set, [Astro's sitemap integration](https://docs.astro.build/en/guides/integrations-guide/sitemap/) produces `dist/sitemap-index.xml` and numbered sitemap files such as `dist/sitemap-0.xml`. The index references the numbered files, which contain eligible static page URLs. Page URLs use the configured production origin and the agreed path form: `/` for the homepage, no trailing slash or `.html` suffix for other pages.

The [robots.txt endpoint](../src/pages/robots.txt.ts) generates `dist/robots.txt` with `User-agent: *`, `Allow: /`, and an absolute `Sitemap` URL pointing to `sitemap-index.xml`. Keep its sitemap reference derived from the production URL; do not add a second robots.txt under `public/`.

While `production_url` is undecided, a build succeeds with a warning, omits the sitemap, and generates allow-all robots.txt without a `Sitemap` line. Set `production_url` when the production URL is approved and rebuild: that next build generates the sitemap and its robots.txt reference automatically. There is no separate generation step and no automated launch gate. Manually verify the files before launch.

## Include and exclude pages

Every eligible statically generated page is included by default. This includes routes generated by `getStaticPaths()`. Projects that add on-demand routes or externally managed pages must review the integration's discovery limits and configuration for those capabilities.

Edit the exported `sitemapExclusions` list in [astro.config.mjs](../astro.config.mjs) to record approved project exclusions. An empty list includes every eligible page. For example, if the project approves excluding its thank-you page:

```js
export const sitemapExclusions = ["/thank-you"];
```

Entries are exact, root-relative page paths in the canonical URL form: `/` for the homepage, `/about` for a non-root page, or `/articles/index` for that distinct nested route. Do not include the domain, a trailing slash, a query, a fragment, or a `.html` suffix. A misspelled or differently formatted entry will not match. The integration's `filter` reads this list, so all other eligible pages remain automatic as the site grows. Error pages such as 404/500 and endpoints such as robots.txt are excluded by the integration itself.

**Sitemap exclusion alone does not prevent indexing.** An excluded page is still built, reachable, and discoverable through links. Sitemap exclusions also do not add robots.txt blocking rules. If a project needs indexing controls or access restrictions, define those separately in its approved requirements. This feature supplies no preview-environment access controls.

## Verify configuration changes

Run the checks in [CONTRIBUTING.md](../CONTRIBUTING.md#validate-your-change). Build tests verify the generated files, production URLs, automatic page inclusion, exclusions, and the missing-production-URL behavior.

For a configured project, inspect the generated sitemap index, its referenced sitemap files, and robots.txt after building. Confirm the intended origin, page-path form, and inclusion/exclusion choices. These checks on build output do not establish live crawlability.

Use the human-facing [template Wiki launch checklist](https://github.com/joebaz/web-starter/wiki) for manual sitemap submission, processing checks, and live robots.txt/crawlability verification. Maintain project-specific operational notes and completion evidence in each project's Wiki. Sitemap submission and processing do not guarantee indexing.
