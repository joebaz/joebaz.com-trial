- `check` makes only local reads and GitHub reads. Report each of the following separately, including the observed state and expected state or corrective next step:
  - Canonical label names, colors and descriptions; missing/mismatched labels and unexpected labels. Bootstrap expects the canonical set, without adding `wayfinder:*`.
  - Delete-branch-after-merge enabled.
  - Inspect all linked Projects and identify qualifying same-owner user-level Projects whose Status-name set exactly matches the four contract-required names. Exactly one qualifying Project passes this category; none is missing setup, and multiple qualifying Projects are ambiguity. Both missing and ambiguous results exit `1` overall, with the observed candidates reported for the runbook/Maintainer to resolve. Multiple links alone are not a failure: other nonqualifying Projects may be linked. Option order, ids, colors and descriptions are not acceptance requirements. This check is self-contained: no bootstrap-issue scraping, extra input, or configuration. Distinguish missing setup from inability to inspect Projects, which exits `2`.
  - `CLAUDE.md` is a symlink targeting `AGENTS.md`, rather than a copied file.
  - The Contribution guide contact URL in `.github/ISSUE_TEMPLATE/config.yml` points to this repository's `CONTRIBUTING.md` on its actual default branch.
  - CI run URLs, head SHA, event/branch and conclusion for the checked-out local `HEAD`. Check mode does not depend on discovering a bootstrap PR. Missing, queued/running, failed/cancelled, or inaccessible CI cannot count as a pass; an older green run cannot hide a failing current revision. The runbook separately proves that the bootstrap PR's head equals this local commit and has passing `pull_request` CI.
- Print an overall result only after all checks. Exit `0` only when all required checks pass, `1` for a completed inspection with missing/mismatched/pending setup, and `2` for invalid invocation or an inspection/tool failure. Keep inspecting independent categories when one read fails; never turn an unknown into an empty-success result. Early bootstrap checks are expected to report missing Project/contact/CI until later steps finish.

The runbook owns this approval gate; a script flag or a runbook's existence is not consent. Apply creates or updates canonical labels from the single definition, deletes only GitHub stock labels identified by the labels API's `default: true` and outside that definition, and enables delete-on-merge. Preserve a stock name that overlaps a canonical label and set its canonical metadata. Never delete arbitrary custom labels to achieve an exact-set check: report them for a separate decision. Send `delete_branch_on_merge` as a JSON boolean (`gh api -F delete_branch_on_merge=true` or equivalent JSON), not a raw string. No file edits, Project/wiki/issue operations, branch protection, rulesets, other settings, or CI reruns in apply.
- Make apply repeatable: read current state, perform only the allowed changes, and read back those changes. Exit `0` only when the allowed apply subset is read back successfully; exit `2` on refusal, invalid invocation, read/mutation failure or incomplete readback. On partial failure, report what changed and what failed; do not claim rollback or overall success. A retry repeats only the allowed reconciliation. Its success reports the apply subset, not a false claim that full check mode already passes.
